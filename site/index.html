Computer use for Omarchy

Your agent doesn’t use a computer. It has one.

Argus gives every coding agent on Omarchy many browsers at once. After each action it reports what changed, not what the page looks like, and when a click fails it tells the agent why.

How it works

Report what changed, not what is.

Most tools answer “what does the page look like?”, so the agent looks again after every action and works out the difference itself. Argus answers “what did my action do?”, which is smaller and says more, because it names the cause.

A screenshot

Shows the page after the click.

It can’t say the click hit a cookie banner, that a request failed, or that nothing changed at all. The agent has to infer that from pixels, then pay again to check.

An Argus delta

Says what the click caused.

Text that appeared or left, form fields that filled, requests that failed, console errors, layout that shifted, and when the page settled, measured in the browser rather than guessed.

Why clicks fail

A failed click comes with a diagnosis.

Argus finds elements the way a person describes them, by role and name, and checks what a real click would hit. When it can’t act, it says what’s in the way.

Something is on top of it

Names the element painted over the target.

> click button:Place order
  x covered  button#pay
  covered by div#scrim
  z-index:9998 position:fixed

A question was asked

Dialogs are answered safely and reported, never silently.

> click button:Delete account
  ? confirm  “Delete your account?”
    -> dismissed
  (argus dialog accept, then retry)

Two things share a name

Refuses to guess and lists the candidates.

> click button:Remove
  x ambiguous
  [0] remove  button.row-remove
  [1] remove  button.row-remove

The name is slightly off

Suggests what does exist.

> click button:Place ordr
  x not-found
  did you mean: button:place order

It can’t be clicked yet

Disabled, hidden, zero-size, or offscreen, each named.

> click button:Pay later
  x disabled  button#later
  something upstream must
  enable it first

A picker would have opened

No file dialog opens. Files go straight in.

> click label:Upload avatar
  ? file-chooser  input#avatar
$ argus upload "Upload avatar" me.png
  + “avatar: me.png”

Only on Omarchy

Built into the machine, not bolted onto a browser.

A browser extension only sees its tab, and a library only sees its project. Omarchy is the whole desktop, so Argus can do three things they can’t.

The OS is already an API

440 of Omarchy’s 441 commands describe themselves. Argus serves them to agents in groups, so changing a theme or a sound output is a function call, not a settings screen to click through.

542 tokens, instead of 15,031

The compositor is watching

On a desk lane, Hyprland itself reports a popup opening as a new window or a page going fullscreen. The page can’t see those, so a browser extension can’t either.

window opened · resized · fullscreen

A desk no one sees

Real, headful browsers on a virtual monitor. argus peek brings the desk onto your screen, and a second peek sends it back. Agent windows never take your keyboard focus.

0 focus changes in 45 compositor events

Install

Nothing to download.

Argus uses what Omarchy already ships: Chromium, which includes chromedriver, plus curl, jq, and Hyprland. There’s no Playwright, no Node, and no second copy of a browser.

Drive a browser

Every action returns what it changed.

argus open https://example.com
argus click "link:Learn more"
argus audit

Give it a desk

A real browser on a virtual monitor. Peek when you want to watch.

argus desk up
argus --desk open https://example.com
argus peek

Hand it to your agent

Any agent that speaks MCP gets the browser and the Omarchy command catalogue.

{
  "mcpServers": {
    "argus": { "command": "/home/you/Work/argus/bin/argus-mcp" }
  }
}

Tested on Hyprland 0.56 with Chromium 152. Desk lanes need a Hyprland session.
